# 08. 데이터베이스 설계

> [!summary] 한눈에 보기
> 데이터베이스 설계는 요구사항을 안정적인 스키마와 제약조건으로 변환하는 과정이다. 현재 화면에 필요한 열만 복사하는 것이 아니라 데이터의 의미, 수명주기와 변경 규칙을 반영해야 한다.

## 설계 절차

1. 요구사항 수집과 업무 규칙 확인
2. 개념적 ER 모델 작성
3. 관계 스키마로 변환
4. [[09. 정규화]]로 이상 현상 점검
5. 자료형과 제약조건 결정
6. 인덱스와 물리 구조 결정
7. 테스트 데이터와 질의로 검증

## 명명과 키 설계

- 테이블과 열 이름은 일관된 규칙을 사용한다.
- 기본키는 안정적이고 짧아야 한다.
- 자연키와 대리키의 장단점을 비교한다.
- 외래키와 삭제·수정 정책을 명시한다.

## 자료형 선택

- 금액: 부동소수점보다 고정소수점 또는 최소 통화 단위 정수 검토
- 날짜와 시각: 시간대와 정밀도 결정
- 코드값: 허용 범위와 참조 테이블 고려
- 텍스트: 최대 길이와 다국어 요구 확인

## 인덱스 설계

인덱스는 검색을 빠르게 할 수 있지만 저장 공간과 쓰기 비용이 증가한다. 다음 열이 후보가 될 수 있다.

- 자주 검색하거나 조인하는 열
- 선택도가 높은 열
- 정렬과 범위 조건에 자주 사용하는 열

## 설계 검토 질문

- 한 행은 무엇을 의미하는가?
- 기본키는 시간이 지나도 안정적인가?
- 한 열에 여러 값이 들어가지는 않는가?
- 삭제 시 과거 기록을 유지해야 하는가?
- 개인정보와 민감정보를 분리해야 하는가?
- 주요 질의를 효율적으로 수행할 수 있는가?

## 자주 하는 실수

- 현재 보고서 형식을 그대로 테이블 구조로 사용한다.
- 의미가 다른 값을 하나의 범용 코드 열에 저장한다.
- 성능을 이유로 검증 없이 중복 데이터를 만든다.
- 보안과 보존 기간을 설계 마지막에 고려한다.
