# 10. 회복과 동시성 제어

> [!summary] 한눈에 보기
> 트랜잭션은 하나의 논리적 작업 단위다. 회복은 장애 후 일관된 상태로 돌아가게 하고, 동시성 제어는 여러 트랜잭션이 동시에 실행될 때 잘못된 간섭을 방지한다.

## ACID 특성

- **원자성:** 전부 실행되거나 전부 취소된다.
- **일관성:** 트랜잭션 전후에 제약조건을 만족한다.
- **격리성:** 동시에 실행되어도 적절한 직렬 실행처럼 보인다.
- **지속성:** 커밋된 결과는 장애 후에도 유지된다.

## 트랜잭션 예제

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 10000
WHERE account_id = 1;

UPDATE accounts
SET balance = balance + 10000
WHERE account_id = 2;

COMMIT;
```

두 번째 갱신이 실패하면 첫 번째 갱신도 `ROLLBACK`되어야 이체 금액이 사라지지 않는다. 트랜잭션 시작 문법은 DBMS마다 다를 수 있다.

## 동시 실행 문제

- 갱신 손실
- 오손 읽기
- 반복 불가능 읽기
- 팬텀 읽기

## 제어 방법

- 공유·배타 잠금
- 2단계 잠금 규약
- 타임스탬프 순서
- 다중 버전 동시성 제어
- 격리 수준 설정

## 회복

로그에는 변경 전후 정보나 재실행에 필요한 기록을 저장한다. 일반적인 회복은 커밋된 작업을 재실행하고 미완료 작업을 취소한다.

## 교착상태

두 트랜잭션이 서로 상대방의 잠금을 기다리면 교착상태가 발생한다. DBMS는 대기 그래프나 시간 제한으로 감지하고 한 트랜잭션을 중단할 수 있다.

## 자주 하는 실수

- 여러 SQL 문을 하나의 트랜잭션으로 묶지 않는다.
- 격리 수준을 높이면 비용 없이 안전성만 증가한다고 생각한다.
- 응용프로그램 오류와 데이터베이스 장애 회복을 구분하지 않는다.
- 트랜잭션을 오래 유지해 잠금 경합을 키운다.
