# 03. 데이터 모델링

> [!summary] 한눈에 보기
> 데이터 모델링은 현실의 대상과 업무 규칙을 데이터 구조로 추상화하는 과정이다. 개체, 속성, 관계와 제약조건을 정의한 뒤 관계형 스키마로 변환한다.

## 모델링 단계

1. **개념적 모델링:** 업무 개념을 ER 다이어그램으로 표현
2. **논리적 모델링:** 관계형 테이블과 키로 변환
3. **물리적 모델링:** 자료형, 인덱스와 저장 방식을 결정

## ER 모델의 구성 요소

- **개체:** 독립적으로 식별할 대상
- **속성:** 개체가 가진 특성
- **관계:** 개체 사이의 연관성
- **식별자:** 개체를 고유하게 구분하는 속성
- **카디널리티:** 일대일, 일대다, 다대다 관계
- **참여 제약:** 관계 참여가 필수인지 선택인지 표시

## 예제

학생은 여러 과목을 수강하고 한 과목에는 여러 학생이 참여한다. 학생과 과목은 다대다 관계이므로 `수강`이라는 연결 개체가 필요하다.

```text
학생 1 ── N 수강 N ── 1 과목
```

`수강`에는 신청일, 성적과 같은 관계 자체의 속성을 저장할 수 있다.

## 요구사항에서 규칙 찾기

문장에 숨어 있는 규칙을 명시해야 한다.

- 한 주문은 반드시 한 고객에게 속한다.
- 한 주문에는 하나 이상의 상품이 포함된다.
- 한 이메일은 두 고객이 공유할 수 없다.
- 삭제된 상품의 과거 주문 기록은 유지한다.

## 자주 하는 실수

- 화면이나 Excel 열을 그대로 테이블로 옮긴다.
- 다대다 관계를 연결 테이블 없이 구현한다.
- 업무 규칙을 담당자의 기억에만 의존한다.
- 속성 하나에 여러 값을 쉼표로 저장한다.
