# 12. R과 데이터베이스 연동

> [!summary] 한눈에 보기
> R은 DBI 인터페이스와 DBMS별 드라이버를 사용해 데이터베이스에 연결한다. 필요한 데이터를 SQL에서 먼저 필터링하고 R에서는 통계 분석과 시각화를 수행하면 메모리 사용과 데이터 이동을 줄일 수 있다.

## 기본 구성

- `DBI`: 공통 데이터베이스 인터페이스
- DBMS 드라이버: `RSQLite`, `RPostgres` 등
- 접속 정보: 서버, 포트, 데이터베이스, 사용자와 비밀번호
- SQL 쿼리

## SQLite 재현 예제

```r
library(DBI)

connection <- dbConnect(RSQLite::SQLite(), ":memory:")

sales <- data.frame(
  category = c("A", "A", "B"),
  amount = c(100, 150, 200)
)

dbWriteTable(connection, "sales", sales)

result <- dbGetQuery(
  connection,
  "SELECT category, AVG(amount) AS average_amount
   FROM sales
   GROUP BY category"
)

print(result)
dbDisconnect(connection)
```

코드에는 입력 데이터가 포함되어 있지만 출력은 실제 R 환경에서 실행해 확인해야 한다.

## 매개변수화된 쿼리

```r
query <- "SELECT category, amount
          FROM sales
          WHERE amount >= ?"

result <- dbGetQuery(
  connection,
  query,
  params = list(150)
)
```

지원되는 매개변수 문법은 드라이버에 따라 확인한다.

## 큰 데이터 처리

전체 테이블을 R로 가져오기 전에 SQL에서 필요한 범위를 줄인다.

```sql
SELECT order_date, category, amount
FROM sales
WHERE order_date >= '2026-01-01'
  AND amount IS NOT NULL;
```

## 접속 정보 보안

```r
password <- Sys.getenv("DB_PASSWORD")
```

비밀번호를 노트, 스크립트나 Git 저장소에 직접 기록하지 않는다. 환경변수나 안전한 비밀 관리 도구를 사용한다.

## 데이터 누수 점검

머신러닝 데이터를 SQL로 추출할 때 예측 기준일 이후의 정보가 포함되지 않도록 공개 시점과 조인 조건을 확인한다.

## 자주 하는 실수

- 전체 운영 테이블을 매번 R 메모리로 가져온다.
- 쿼리 문자열에 사용자 입력을 직접 연결한다.
- 분석 종료 후 연결을 닫지 않는다.
- 시간대와 날짜 자료형을 문자열로만 처리한다.
- 운영 데이터베이스에서 무거운 분석 쿼리를 제한 없이 실행한다.
