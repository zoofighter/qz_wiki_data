# 07. SQL 고급

> [!summary] 한눈에 보기
> 고급 SQL은 여러 테이블의 조인, 서브쿼리, 공통 테이블 표현식과 윈도 함수로 복잡한 분석 질문을 표현한다. 결과가 맞는 것뿐 아니라 중복 행과 NULL의 영향을 점검해야 한다.

## 조인

```sql
SELECT
    c.customer_id,
    c.customer_name,
    o.order_id,
    o.order_date
FROM customers AS c
LEFT JOIN orders AS o
  ON c.customer_id = o.customer_id;
```

`LEFT JOIN`은 주문이 없는 고객도 유지한다. `INNER JOIN`은 양쪽에 일치하는 행만 반환한다.

## 서브쿼리

```sql
SELECT product_name, price
FROM products
WHERE price > (
    SELECT AVG(price)
    FROM products
);
```

## 공통 테이블 표현식

```sql
WITH customer_totals AS (
    SELECT
        customer_id,
        SUM(order_amount) AS total_amount
    FROM orders
    GROUP BY customer_id
)
SELECT customer_id, total_amount
FROM customer_totals
WHERE total_amount >= 100000;
```

## 윈도 함수

```sql
SELECT
    customer_id,
    order_date,
    order_amount,
    SUM(order_amount) OVER (
        PARTITION BY customer_id
        ORDER BY order_date
    ) AS cumulative_amount
FROM orders;
```

윈도 함수는 행을 하나로 축약하지 않고 각 행에 집계 결과를 추가한다.

## 중복 행 점검

일대다 조인에서는 왼쪽 테이블의 행이 여러 번 나타난다. 조인 후 `COUNT(*)`가 증가했다고 데이터가 새로 생긴 것은 아니다.

## 실행 계획

DBMS별 `EXPLAIN` 기능으로 인덱스 사용, 조인 순서와 전체 테이블 탐색 여부를 확인할 수 있다. 문법과 출력은 DBMS마다 다르다.

## 자주 하는 실수

- 조인 키가 유일하지 않은 사실을 무시한다.
- `LEFT JOIN` 후 오른쪽 테이블 조건을 `WHERE`에 두어 사실상 내부 조인으로 바꾼다.
- 윈도 함수와 `GROUP BY` 집계의 행 수 차이를 이해하지 않는다.
- 성능 개선 없이 모든 열에 인덱스를 추가한다.
