# 11. 데이터베이스 보안과 권한

> [!summary] 한눈에 보기
> 데이터베이스 보안은 기밀성, 무결성과 가용성을 보호한다. 사용자는 업무에 필요한 최소 권한만 가져야 하며 인증, 권한 부여, 암호화, 감사와 안전한 쿼리를 함께 적용한다.

## 최소 권한 원칙

분석 사용자가 조회만 필요하다면 `SELECT` 권한만 부여하고 테이블 삭제나 사용자 관리 권한은 주지 않는다.

```sql
GRANT SELECT ON sales_summary TO analyst_role;
REVOKE DELETE ON sales_summary FROM analyst_role;
```

권한 문법과 역할 기능은 DBMS마다 다르다.

## 주요 보안 통제

- 사용자 인증
- 역할 기반 접근 제어
- 행·열 수준 권한
- 저장·전송 구간 암호화
- 비밀번호와 키의 안전한 저장
- 접근 로그와 감사
- 백업 보호와 복구 시험
- 개인정보 마스킹

## SQL 인젝션 방지

사용자 입력을 문자열 연결로 SQL에 삽입하지 않는다.

```python
cursor.execute(
    "SELECT customer_id, name FROM customers WHERE email = ?",
    (email_input,),
)
```

위 플레이스홀더 문법은 Python DB 드라이버에 따라 달라질 수 있다. 핵심은 매개변수화된 쿼리를 사용하는 것이다.

## 민감정보 관리

- 비밀번호 원문을 저장하지 않는다.
- API 키와 접속 문자열을 코드에 직접 기록하지 않는다.
- 운영 데이터의 개인정보를 학습용 파일로 복사하지 않는다.
- 공개 분석에서는 재식별 위험을 점검한다.

## 자주 하는 실수

- 내부망이면 인증과 암호화가 필요 없다고 생각한다.
- 모든 분석가에게 관리자 권한을 준다.
- 데이터 백업 파일의 접근 권한을 확인하지 않는다.
- 문자열 필터링만으로 SQL 인젝션을 막으려 한다.
